# 第二阶段开发说明

## 阶段定位

在第一阶段“可运行、可展示、可发布”的基础上，第二阶段聚焦“可阅读、可发现、可持续更新”的博客能力建设。

本阶段的核心目标不是再堆页面，而是完善内容组织结构、阅读链路和站点基础能力，让站点从作品展示升级为完整博客系统。

## 阶段目标

1. 建立完整内容体系：标签、归档、搜索三大入口打通。
2. 增强阅读连续性：上一篇/下一篇、相关推荐、系列化阅读。
3. 补齐站点基础页：About、Now、404、基础 SEO 支撑。
4. 提升可运营性：统一文档规范、发布检查清单、阶段验收机制。

## 范围（In Scope）

### 1) 内容发现与组织

- 标签页（按标签聚合文章）
- 归档页（按年月分组）
- 站内搜索（标题/摘要/标签）
- 首页文章区支持快速筛选（可选）

### 2) 阅读体验增强

- 文章页增加：
  - 上一篇 / 下一篇
  - 相关推荐（同标签优先）
  - 阅读时长估算
  - 更新时间展示

### 3) 基础页面补齐

- About 页面（完整个人介绍）
- Now 页面（近期状态/计划）
- 404 页面（统一视觉风格）

### 4) 站点可见性基础（轻量）

- 每页基础 meta（title/description）
- Open Graph 基础字段（至少首页与文章页）
- `sitemap.xml`（静态生成或维护）
- `robots.txt`

## 非范围（Out of Scope）

以下内容不在第二阶段主线内，仅做记录，放入第三阶段：

- 后端鉴权体系（登录、角色权限）
- AI key 完整后端代理迁移
- 完整安全加固（XSS 全面策略、速率限制）
- CI/CD、自动化部署、监控告警

## 任务拆解（WBS）

## 模块 A：内容体系

### A1 标签系统

- [ ] 定义标签聚合数据结构（来源于 `db.json`）
- [ ] 新增标签页模板（`tags.html`）
- [ ] 增加标签页脚本与渲染逻辑（`tags.js`）
- [ ] 标签入口接入首页和文章页

验收标准：

- 任意标签可查看对应文章列表；
- 空标签不会渲染异常；
- 与现有站点样式一致。

### A2 归档系统

- [ ] 新增归档页（`archive.html`）
- [ ] 文章按 `YYYY-MM` 分组展示
- [ ] 每月文章数统计

验收标准：

- 归档按时间倒序；
- 每篇文章可跳转详情页；
- 月份分组正确。

### A3 搜索系统

- [ ] 设计前端轻量搜索（本地数据过滤）
- [ ] 支持标题/摘要/标签关键词匹配
- [ ] 增加空结果状态展示

验收标准：

- 搜索结果响应流畅；
- 关键词匹配准确；
- 无输入时显示默认列表。

## 模块 B：阅读链路

### B1 上下篇导航

- [ ] 在 `article.html` 增加上一篇/下一篇区域
- [ ] 按发布时间或文章顺序生成前后关系

验收标准：

- 首篇无上一篇、末篇无下一篇时处理正确；
- 链接准确无循环跳转。

### B2 相关推荐

- [ ] 基于共享标签计算推荐候选
- [ ] 至少展示 2-3 篇（不足时降级展示最新文章）

验收标准：

- 推荐内容不包含当前文章；
- 有标签时优先命中同标签内容。

### B3 阅读时长与更新信息

- [ ] 文章渲染后统计字数并估算阅读时长
- [ ] 展示“最后更新于”字段（无则回退发布日期）

验收标准：

- 时长估算可解释（例如按每分钟 300 字）；
- 展示逻辑稳定。

## 模块 C：基础页面

### C1 About / Now / 404

- [ ] 新增 `about.html`
- [ ] 新增 `now.html`
- [ ] 新增 `404.html`
- [ ] 统一导航入口与跳转

验收标准：

- 页面可访问；
- 风格与首页一致；
- 404 页面在错误路径可触达（本地可模拟）。

## 模块 D：可见性基础

### D1 SEO 基础

- [ ] 首页和文章页补充基础 meta
- [ ] 添加 OG 关键字段

### D2 站点索引文件

- [ ] 新增 `robots.txt`
- [ ] 维护 `sitemap.xml`

验收标准：

- 页面源码可见 meta；
- 索引文件路径可访问。

## 推荐目录与文件规划

建议在第二阶段新增以下文件（按需）：

- `tags.html`
- `archive.html`
- `about.html`
- `now.html`
- `404.html`
- `tags.js`
- `archive.js`
- `search.js`（可并入 `main.js`）
- `robots.txt`
- `sitemap.xml`

## 数据字段建议（兼容现有结构）

在不破坏当前 `db.json` 的前提下，建议逐步补充：

- `updatedAt`：最后更新时间
- `readingMinutes`：可选，若无则运行时计算
- `series`：可选，系列文章标识
- `cover`：可选，文章封面

## 里程碑计划（建议 2 周）

### Week 1：内容体系落地

- Day 1-2：标签页
- Day 3-4：归档页
- Day 5-6：搜索功能
- Day 7：联调与样式统一

### Week 2：阅读链路 + 基础页

- Day 1-2：上下篇 + 相关推荐
- Day 3：阅读时长 + 更新时间
- Day 4-5：About / Now / 404
- Day 6：SEO 基础 + robots + sitemap
- Day 7：验收与文档补全

## 发布前检查清单

- [ ] 新页面导航可达
- [ ] 页面在移动端无明显布局问题
- [ ] 文章详情链路完整（上下篇/推荐）
- [ ] 搜索结果与标签/归档一致
- [ ] 无新增明显控制台报错
- [ ] 文档已更新到 `docs/`

## 风险与应对

1. 数据字段不齐导致渲染异常  
   - 应对：所有新字段提供兜底逻辑。

2. 搜索与筛选性能下降  
   - 应对：优先前端轻量实现，后续再考虑索引优化。

3. 视觉风格分裂  
   - 应对：统一复用现有变量与组件样式，避免新造体系。

## 阶段完成标准（Definition of Done）

- 完成 In Scope 中 A/B/C/D 四个模块的核心任务；
- 页面与阅读链路可稳定使用；
- 文档与功能状态同步；
- 为第三阶段安全与工程化改造预留清晰接口。
