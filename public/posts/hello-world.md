这是我的第一篇测试文章。在本文中，我将简要记录构建 [Redou 轻量化记忆增强系统](#) 时的底层架构思考，以及我们在向量表征和因果推断中遇到的坑。

## 1. 无状态 (Stateless) 的痛点

传统的 LLM 架构（如基础的 GPT 接口）是完全无状态的。这意味着每次你发送一个请求，你必须把**所有的历史对话上下文**一起打包塞进 Prompt 里。

这种方式带来了两个致命缺陷：
1. **Token 成本呈指数级爆炸**：对话越长，每一轮的成本就越高。
2. **上下文窗口溢出**：一旦超过 128K 或 256K 的模型限制，LLM 就会发生“强制失忆”。

## 2. 向量数据库不是银弹

很多团队在解决记忆问题时，第一反应就是：“把聊天记录存进向量数据库（Vector DB），然后做 RAG（检索增强生成）不就行了？”

我们在早期的测试中也采用了这种做法，结果发现：
* **语义重叠问题**：当你问“我上个月最喜欢去的咖啡馆是哪家？”时，纯语义检索可能会把所有提到“咖啡”的聊天记录都召回，导致模型被噪声淹没。
* **时序混乱**：向量空间里没有“时间”的概念。一个月前说的“我不喜欢加糖”可能比昨天说的“我最近开始尝试全糖咖啡”拥有更高的余弦相似度。

### 2.1 我们引入的解法

为了解决这个问题，我们设计了一套**混合知识图谱提取管道**。

```python
# 混合检索模块伪代码演示
def retrieve_memory(query: str, user_id: str):
    # 1. 解析查询的时间维度与实体
    entities, time_context = nlp_engine.parse(query)
    
    # 2. 从图数据库获取硬性实体关系
    graph_results = neo4j.match(user_id, entities)
    
    # 3. 结合向量进行语义柔性召回
    vector_results = qdrant.search(query_vector, limit=5)
    
    # 4. Reranker 重排
    return reranker.sort(graph_results + vector_results)
```

通过引入图数据库（Graph DB），我们让记忆具有了“方向”和“结构”。

## 3. 动态遗忘机制 (Dynamic Forgetting)

真正的记忆不是“记住一切”，而是“**遗忘无关紧要的东西**”。

我们在 Redou 引擎中内置了一个打分机制。每次记忆被访问时，它的“激活阈值”就会上升。如果一段记忆连续 30 天未被调用，它就会被放入冷存储（Cold Storage），从而保证核心缓存区（Hot Cache）的极速响应。

| 存储层级 | 访问延迟 | 适用场景 | 存储媒介 |
| :--- | :--- | :--- | :--- |
| **Hot Cache** | < 10ms | 当前会话、短期工作记忆 | Redis (内存) |
| **Warm Vector** | ~100ms | 语义相似、相关背景召回 | Qdrant / Milvus |
| **Cold Archive** | > 1s | 长期沉睡的低频数据存档 | S3 / PostgreSQL |

## 结语

状态外包是一场关于**召回精度**与**延迟**的极致平衡游戏。未来，随着模型原生上下文窗口的不断扩大（也许会到 1M 甚至无限），基于外部记忆库的架构可能会演变成一种全新的形态——一种与大模型权重动态融合的“外挂赛博海马体”。
